**1.** *("Make the generated public tree internally publishable".)*

Two classes of broken link to resolve, verbatim:

> **A.** Five routes are broken because the public site currently depends on
> private publication/build machinery: `/licensing/`, `/license/`,
> `/contributing/`, `/code-of-conduct/`, `/env-example/`. Their source documents
> are intended to be public, but the current `scripts/sync_site_pages.py` is
> withheld.
>
> **B.** Eight route families are generated from private sources and must not
> exist publicly: `/decisions/log/`, `/milestones/`, `/research/`,
> `/agent-protocol/`, `/session-protocol/`, `/agents/`, `/decisions/`,
> `/backlog/`. **These must NOT be made public merely to make links pass.**

On the generator: *"If these pages can be generated by a small, public-safe
subset of the existing logic: create a clean public-safe implementation or
refactor the relevant logic… do not make the public repository depend on private
files. If the cleanest solution is to publish a suitably sanitized/trimmed
`sync_site_pages.py`, do that. If another architecture is cleaner, explain it and
implement the smallest safe solution."*

On the private-only links, four options per link — remove, replace with a public
document, rewrite the sentence, or create a new public-safe page — and: *"Do not
blindly replace every link with a generic README link. The resulting public
documentation should read naturally to someone who has never seen the private
repository."*

On the private repository: do not delete private documentation, rewrite project
memory, remove decisions, alter session records, or weaken private docs.

> **IMPORTANT: The goal is not merely to make the checker green by suppressing
> errors. The public tree itself must be genuinely coherent.**

Verification required: `--check`, a fresh temporary tree outside the repository,
the site's own link checker against it, a site build, and confirmation that no
private route, file, denied path or secret is present and the tree is
reproducible. D-048 to be updated rather than duplicated unless a genuinely new
architectural choice was made.

Boundaries: no commit, no push, no public repository, no GitHub settings, no
deployment, no DNS/TLS, no history rewriting.
