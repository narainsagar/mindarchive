==================================================
1. PRODUCT VISION
==================================================

Mind Archive is a fully open-source, local-first application for preserving, organizing, searching, managing, and exporting a user's AI conversations, memories, knowledge, files, and related personal information.

The user should own their data.

The application must NOT be dependent on a particular AI company.

It should work with exports/data from:

- ChatGPT / OpenAI
- Claude / Anthropic
- Google Gemini
- Google AI Studio
- Other AI assistants
- Local/self-hosted AI systems
- Future providers

ChatGPT is an initial importer target, NOT the architectural center of the application.

The long-term goal is to create a personal AI knowledge/archive system that remains useful even if the user changes AI providers.

==================================================
7. ARCHITECTURE
==================================================

Use clean modular architecture.

Conceptually:

Web UI
   |
   v
API/Application layer
   |
   +---- Importer system
   |
   +---- Archive system
   |
   +---- Search system
   |
   +---- Event system
   |
   +---- Storage adapters
   |
   +---- Sync adapters
   |
   +---- Configuration
   |
   v
Local filesystem + SQLite

Importer providers must be adapters/plugins.

Example:

Importer
  -> detect source
  -> parse source
  -> normalize data
  -> validate
  -> create archive objects
  -> emit events
  -> persist locally

Do not tightly couple the entire application to one import format.

==================================================
8. EVENT-DRIVEN DESIGN
==================================================

Prefer event-driven workflows.

Do NOT design important workflows around arbitrary timers or polling if an event-based solution is practical.

Examples:

archive.imported
conversation.created
conversation.updated
document.created
document.indexed
search.indexed
backup.requested
backup.completed
sync.started
sync.completed
sync.failed

Milestone 1 does NOT need a complicated distributed event bus.

Create clean internal interfaces first.

Use the simplest implementation that works.

Upgrade the event infrastructure only when required.
